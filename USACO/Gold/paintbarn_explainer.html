Painting the Barn

Farmer John wants the most barn possible under exactly k coats of paint, and he is allowed two more rectangles to get there. The whole problem collapses once you notice the two rectangles can never overlap.

The shape of the problem

The barn is a 200 × 200 grid of unit cells. Coordinates run 0…200, so cell (i, j) is the square [i−1, i] × [j−1, j] and the cells are numbered 1…200. Farmer John has already painted n rectangles; you count how many cells carry exactly k coats, then add up to two more disjoint rectangles to push that count as high as it goes.

Two things make this tractable. The grid is tiny and fixed — 40,000 cells no matter how large n gets. And the two new rectangles are disjoint, which is a much stronger constraint than it looks.

01

Count the coats without touching every cell

With n up to 105 and rectangles up to 200 × 200, painting cell by cell is 4 billion operations. A 2D difference array marks four corners per rectangle instead, then one prefix-sum pass over the fixed grid recovers every count.

// Shift by one so the rectangle covers cells [x1, x2-1] x [y1, y2-1].
x1++; y1++; x2++; y2++;
cnt[x1][y1]++;
cnt[x2][y1]--;
cnt[x1][y2]--;
cnt[x2][y2]++;

The ++ shift is what makes the half-open rectangle line up with 1-indexed cells — a rectangle given as (x1,y1)–(x2,y2) covers cells x1…x2−1, and shifting turns that into the clean corner pattern above.

The sweep that follows is O(200²) regardless of n, and it does double duty — it also builds the score grid from stage 2 in the same pass.

02

Turn coats into a score

Here is the move the whole solution rests on. Because the two new rectangles are disjoint, no cell is ever painted twice. Each cell inside a new rectangle gains exactly one coat, never two. So a cell's contribution doesn't depend on which rectangle covers it, or on the other rectangle at all — only on what the cell already had:

  • at k−1 coats it climbs to k — worth +1
  • at k coats it overshoots to k+1 — worth −1
  • anywhere else it makes no difference — worth 0
base += (cnt[i][j] == k);
val[i][j] = (cnt[i][j] == k - 1) - (cnt[i][j] == k);

Counting coats has become picking two disjoint rectangles of maximum total sum over a fixed 200 × 200 integer grid. The original k never appears again.

03

Why two rectangles cost no more than one

The separating cut

Two disjoint axis-parallel rectangles can always be split by a single straight line — vertical or horizontal. If their x-ranges overlap and their y-ranges overlap, they necessarily share area, which the problem forbids. So at least one coordinate must miss, and a cut across that coordinate separates them.

That turns an intractable-looking pairing problem into two independent sweeps. For each of the 199 vertical cut positions, take the best rectangle entirely to the left and the best entirely to the right; then do the same for horizontal cuts. No pair is ever examined directly.

04

Best rectangle on each side of the cut

What remains is maximum-subrectangle-sum, and the standard sweep solves it. Fix a left column a, slide the right column b outward, and maintain runSum[i], the sum of column band [a, b] at row i. Kadane over that 1D array gives the best rectangle whose columns are exactly [a, b].

for (int b = a; b <= SZ; b++) {
    int cur = NEG, best = NEG;
    for (int i = 1; i <= SZ; i++) {
        runSum[i] += transposed ? val[b][i] : val[i][b];
        cur  = max(runSum[i], cur + runSum[i]);
        best = max(best, cur);
    }
    endAt[b]   = max(endAt[b], best);
    startAt[a] = max(startAt[a], best);
}

Each result is filed twice — under its last column in endAt and its first column in startAt. A prefix max over one and a suffix max over the other give exactly what the cut needs:

for (int c = 1; c <= SZ; c++) bestL[c] = max(bestL[c - 1], endAt[c]);
for (int c = SZ; c >= 1; c--) bestR[c] = max(bestR[c + 1], startAt[c]);

The transposed flag reads the grid the other way round, so one function serves both cut directions.

05

Combine, and let zero win when it should

int gain = 0;                     // painting nothing is always allowed

solveAxis(false);                 // split by a vertical line
gain = max(gain, bestL[SZ]);      // best single rectangle
for (int c = 1; c < SZ; c++) gain = max(gain, bestL[c] + bestR[c + 1]);

solveAxis(true);                  // split by a horizontal line
for (int c = 1; c < SZ; c++) gain = max(gain, bestL[c] + bestR[c + 1]);

ofstream("paintbarn.out") << base + gain << endl;

Farmer John may paint fewer than two rectangles, and both cases fall out for free. Zero rectangles is the gain = 0 initialiser — if every rectangle on the board has a negative score, painting nothing wins. One rectangle is bestL[SZ], the best rectangle anywhere in the barn with no cut at all.

Kadane is seeded at NEG rather than 0, so it always returns a non-empty block. That matters: the problem demands positive area, and a silently empty rectangle would be an illegal answer that happened to score zero.

The sample, worked

Three rectangles, k = 2. Fourteen cells already carry exactly two coats. The best pair of new rectangles adds twelve more, and the two of them are separated by a horizontal cut.

Cost

Reading input is O(n). Everything after is fixed at grid size: the difference sweep is O(200²), and each call to solveAxis is O(200³) — roughly 8 million operations, run twice. Memory is a handful of 202 × 202 int arrays. On the worst legal input, 105 rectangles, it finishes in 0.03 seconds.

Verified against an exhaustive brute force over every disjoint rectangle pair on an 8 × 8 barn (600/600), and against an independent implementation on 400 random full-size cases.
